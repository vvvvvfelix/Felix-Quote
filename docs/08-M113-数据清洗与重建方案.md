## 0. 为什么是「删库重建」而不是「原地补迁移」

`data/weigear.db` 的实测现状（团队负责人 2026-11-01 核实）：

| 项 | 现状 | 说明 |
|---|---|---|
| `users` 列 | 只有 `id`/`org_unit_id`/`dept_id` | M004 的 `_v011` **从未落到这个库** |
| `org_unit_id IS NULL` | 21 个用户里 **3 个** | 有孤儿用户 |
| `user_version` | **0** | 迁移版本号没 bump，等于从没跑过迁移链 |

原地补迁移要在**一份结构残缺 + 版本号为 0 + 有孤儿数据**的库上做，且补完之后占位数据
（伟格、`WG-2026-FELIX-0001`）还留在里面，等于白做一遍。删库重建则：

1. 新库从头跑完 `_v001`~`_v014`，缺列问题与 `user_version=0` **一并消失**；
2. 虚构种子顺带满足「全部替换为虚构数据」；
3. 不用为「怎么在残缺结构上补列」写一次性补丁代码。

代价是开发期库里的历史数据全丢 —— 因此**先归档再删**（见步骤 1）。

## 3.5 角色不变量要做成启动期自检（PM 建议，已采纳；改 `src/`，冻结解除后落地）

**为什么不能只靠清洗清单**：清单只能防 M113 这一次的误改。以后任何一次种子调整、角色库调整、
客户自己改角色编码，都可能再次触发同一种**静默失效**——流程「无人可审 → 自动通过」，
界面上一切正常，只是审批流形同虚设。这类问题必须让系统自己喊出来，而不是靠人记得勾清单。

设计（两层，缺一不可）：

**第 1 层 · 启动期体检（新）**
- 新增 `core/workflow.py::audit_definition_health() -> list[dict]`：
  遍历所有启用中的流程定义，对每个 `assignee.role` 型审批节点，检查库里是否存在
  「该角色 + `is_active=1`」的用户；不存在即产出一条问题记录
  `{def_code, node_id, role, kind: "no_approver"}`。
- 由 `modules/workflow.py::seed_workflows()` 在启动时调用，逐条写 **service.log**（`_log_exc`）。
  **不写 audit_logs** —— 这是系统健康信号，不是用户操作痕迹，写审计会让每次启动都刷一堆日志。
- 覆盖面是**所有流程定义**（请假、报销、以及未来的采购/用章），不只报销。

**第 2 层 · 运行期兜底（改现有行为）**
- `_activate_node()` 在「无人可审 → 自动通过」时已经会写一条 `workflow_logs`，
  但没人看 workflow_logs。改为**同时写 service.log 告警**（含 def / instance / node / role），
  让「这一档又秒过了」在运维日志里可查、可告警。
- 刻意**不做成硬性报错**：有节点临时无人（如岗位空缺）是合理业务状态，
  硬拦会让流程卡死；目标是「让人看见」，不是「替人决定」。

## 4. 员工组织范围过滤的三条前置（团队负责人决定一 · 落地条目）

员工花名册套 `P.scope_clause_org` 之前，必须三条全满足，否则会直接把花名册对所有人搞成空白
（`scope_clause_org` 找不到归属时保守返回 `1=0`）：

1. **结构前置**：库补齐到 **`_v014`**（含 M006 的 `_v014` 工号纠正迁移），
   `company_id` / `current_org_unit_id` 列存在且 `user_version` 正确 bump
   → M113 删库重建后**自动满足**（M006 在前，故重建后版本号为 **14**）
2. **数据前置**：回填 `org_unit_id IS NULL` 的用户，孤儿数为 0
   → M113 后需单独校验（虚构种子本身不应产生孤儿）
3. **口径前置（需用户/PM 拍板，不是工程能单方定的）**：**「无归属用户」的兜底行为是什么**
   - 现在 `scope_clause_org` 找不到归属 → `1=0` → 看不见
   - 但对 `scope=all` 的管理员来说，合理预期可能是「全可见」
   - 当前实现不区分 `scope=all` 与「查不到归属」，一律 `1=0`，这是**保守过头**
   - 建议口径（待拍板）：`scope=all` 直接放行不过滤；其他 scope 查不到归属才 `1=0` 并记一条告警日志
