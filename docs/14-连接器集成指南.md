# M120 连接器集成指南（企业微信 / 钉钉 / 飞书）

> 面向交付与运维：怎么把 Felix 企业管理平台接到企业 IM 的 SSO 上。
> 代码：`src/app/modules/connectors.py`；配置页：前端「连接器」（`src/app/static/js/pages/connectors.js`）。
> 登录入口：`src/app/static/js/app.js` 的 `wecomSso()`（企业微信 UA 自动跳转）。

## 1. 企业微信接入步骤

### 1.1 企微后台准备
1. 登录 [企业微信管理后台](https://work.weixin.qq.com/) →「我的企业」→ 复制 **企业ID（CorpID）**。
2. 「应用管理」→ 自建应用 → 记录 **AgentID** 与 **Secret**。
3. 「网页授权及 JS-SDK」→ 配置**可信域名**（填部署域名，不含 `http://`）与**可信 IP**。
4. 把下面的**回调地址**填到应用的网页授权回调处（本系统已暴露该路由）：

   ```
   https://<你的域名>/api/connectors/wecom/callback
   ```

   配置页会自动算出并显示这个地址，可一键复制。

### 1.2 在本系统配置
管理员登录 → 左侧「**连接器**」→ 填入 CorpID / AgentID / Secret → 勾选「启用企业微信登录」→ 保存。

- Secret 在读取时后端脱敏为 `******`，**永不回传明文**；
- Secret 输入框留空保存 → 后端保留原密钥（方便只改开关）；
- 每次保存都会写审计日志（`audit`）。

### 1.3 登录链路
1. 用户在**企业微信内置浏览器**打开系统 → `wecomSso()` 检测 UA（`MicroMessenger|wxwork`）。
2. 未登录 → 拉 `/api/connectors/wecom/authorize-url` → 跳企微授权页。
3. 授权后企微带 `code` 回调 → `/api/connectors/wecom/callback`
   用 code 换 userid → 匹配内部用户 → 签发与本地登录相同的 Bearer token。
4. 前端存 token 并清掉地址栏的 `code/state`，进入正常界面。

**账号匹配规则（重要）**：内部用户的**登录名（username）**必须等于企业微信 **userid**。
未匹配时返回 `matched:false` 并提示「请联系管理员绑定」，**不会放行**。

### 1.4 相关接口
| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/connectors/wecom/config` | admin | 读配置（secret 脱敏） |
| POST | `/api/connectors/wecom/config` | admin | 写配置（审计） |
| GET | `/api/connectors/wecom/authorize-url` | 公开 | 取授权地址；未启用返回 `enabled:false` |
| GET | `/api/connectors/wecom/callback` | 公开 | code → userid → token |

配置存储键：`settings.connector:wecom`（单列 JSON，与 M006 品牌键完全隔离）。

## 2. 钉钉 / 飞书：如何补齐（给下一任）

基类 `ConnectorBase` 已定义好接口，只需实现两个方法：

```python
class DingTalkConnector(ConnectorBase):
    code, name = "dingtalk", "钉钉"
    def authorize_url(self, redirect_uri, state=""): ...   # 拼扫码登录地址
    def exchange_code(self, code): ...                      # code -> userinfo
```

再补一组路由（照抄 wecom 的四个即可）：
- `GET/POST /api/connectors/dingtalk/config`
- `GET /api/connectors/dingtalk/authorize-url`
- `GET /api/connectors/dingtalk/callback`

建议 settings 键：`connector:dingtalk` / `connector:feishu`（与 `connector:wecom` 同构）。
前端配置页 `connectors.js` 里钉钉/飞书那块表格已写明「后续要做」，补齐后把状态从「占位」改掉即可。

## 3. 已知限制与未验证项

1. **未做真实联调**：本环境没有企业微信 CorpID/Secret/AgentID，
   OAuth 往返（换 token、取 userinfo）**没有跑通过真实请求**，只保证代码路径与配置页完整。
   首次部署请务必用真实凭据走一遍 §1.3 的链路。
2. 连接器模块按 M001 起的模块开关机制装配（`registry.py` 里 `code=connectors`），
   关掉该模块则整组路由不挂载。
3. 账号绑定目前只按 `username == userid` 匹配；如需「企微 userid 独立字段绑定」，
   需给 users 表加列并改回调匹配逻辑。
4. 钉钉/飞书仅为占位，见 §0 与 §2。
