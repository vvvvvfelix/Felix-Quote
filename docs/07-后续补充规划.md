## 三、用户四项诉求的落地拆解

### 3.1 服务器与数据库配置套件

#### 3.1.1 六类部署形态的产品定义

| 形态 | 推荐数据放置 | 必要前置 | 产品判断 |
|---|---|---|---|
| 1. 本地单机（应用+库同机） | SQLite 与上传文件在本机 SSD，定时备份到另一磁盘/NAS | M104、M107 | 当前最接近可交付；适合 50 人以内，但仍需恢复演练。 |
| 2. 本地应用+本地存储服务器（两台） | 若“存储”只是附件/备份：SQLite 留应用机；若“存储”指主数据库：应使用 SQL Server | M108、M107 | **禁止把 WAL 模式 SQLite 主库直接放 SMB/NAS 共享目录**；需用户明确“存储服务器”的含义。 |
| 3. 云服务器单机（云盘+对象存储） | 应用+SQLite 在单台云主机块存储，对象存储放备份/附件归档 | M107、对象存储适配 | 可做中小规模；不支持多实例同时写同一 SQLite。 |
| 4. 云主机+云数据库（计算存储分离） | 应用在云主机，SQL Server 在同 VPC 云数据库 | M108、TLS/连接池/迁移工具 | M108 前不可承诺；数据库端口只允许应用安全组访问。 |
| 5. 云计算+本地数据 | 云应用通过专线/VPN 访问本地 SQL Server；不得公网裸露数据库 | M108、VPN/专线、断网降级 | 时延、抖动、断网风险最高，默认应标“审慎/不推荐”，必须做链路压测与 RTO 决策。 |
| 6. 本地计算+云存储 | 主库仍在本地；对象存储用于附件、备份、归档 | M107、对象存储适配 | 适合作为默认混合云方案；对象存储不应直接承载在线 SQLite 文件。 |

#### 3.1.2 推荐器输入与初始配置档位

推荐器至少采集：员工总数、峰值并发、日新增单据、附件日增量/保留年限、报表峰值、厂区数量、RPO/RTO、是否必须 HA、服务器 OS、数据库偏好、云厂商、预算、是否允许公网、是否已有 VPN/NAS/域控。

| 档位 | 建议触发条件 | 初始建议（需压测校准） |
|---|---|---|
| S | 1–20 人、峰值并发 ≤5 | 4 核 / 8 GB / 100 GB SSD；单机 SQLite；每日备份 |
| M | 21–50 人、峰值并发 ≤15 | 8 核 / 16 GB / 300 GB NVMe；单进程 SQLite；附件与备份分盘 |
| L | 51–200 人或跨厂区 | 应用 8 核 / 16 GB；数据库 8 核 / 32 GB / 500 GB SSD 起；完成 M108 后采用 SQL Server |
| XL | >200 人、HA、秒级恢复 | 当前单进程架构不自动给“可部署”结论，转为架构评估，不用堆硬件掩盖架构边界 |

配置不能只按人数硬编码。每档需以模拟真实数据量验证：常用 CRUD 的 P95、列表查询、审批、打印报表、备份耗时和恢复耗时，并把测试版本、数据规模和结论写进推荐规则。

#### 3.1.3 可执行顺序

1. **M108**：先让 SQL Server 可运行，否则六类方案中至少 2/4/5 只是纸面配置。  
2. **M114**：需求问卷 → 拓扑评分 → 配置/风险/费用要素建议 → 不支持项明确拦截。  
3. **M115**：按方案检查 CPU、内存、磁盘类型与空间、端口、时钟、DNS、网络时延、ODBC、SQL Server、对象存储、权限、证书、备份目录。  
4. 生成 `deploy/profiles/<customer>.json`、应用环境文件、数据库配置、反向代理/服务配置，以及桌面 `Felix_环境修复方案_<时间>.html|txt`。密码不得写入普通报告。  
5. **M116**：桌面配置管理器提供模块勾选、配置校验、一键写入、服务启动/停止/重启、开机计划、健康状态、日志入口。  
6. 防火墙按最小权限生成：应用端口、HTTPS、SQL Server、备份/NAS、RDP/SSH分别列规则、来源 CIDR、用途、风险和回滚命令；默认不开放公网 3389/1433/445。  
7. 远程桌面/防火墙修改必须由**本机管理员桌面助手/UAC 提权脚本**执行，不能把系统管理员能力暴露为可远程调用的普通 FastAPI 接口。  
8. 完成备份、恢复、配置回滚和断网演练后才标记部署成功。

#### 3.1.4 当前代码需先修的具体问题

- `deploy/setup.py` 中 `phase_detect(port, db)` 与 `main()` 传入三参数的调用不一致，应纳入部署入口回归。
- `dbconfig.json` / `deploy.conf` 当前可能落明文 SQL Server 密码；部署报告还会写管理员口令。应改为凭据保险箱/环境注入，并对日志脱敏。
- `deploy/control.py` 只显式传 `WEIGEAR_DB`，数据库后端与连接凭据继承链需统一，避免控制台启动与部署配置不一致。
- `platform/status` 目前只看 PID、库大小、表数；应补 CPU/内存/磁盘、数据库连接、备份新鲜度、队列积压、证书到期、最近错误与模块健康。
- Windows 当前是 bat/进程方式；若用户所说“新建服务”是严格的 Windows Service，需要 WinSW 等外部组件或改为任务计划程序，须先拍板。

### 3.2 国内行业字段模板

#### 3.2.1 建议模型

不建议给每个行业直接增加数据库列。建议 M117 建以下元数据：

- `industry_catalog`：行业编码、名称、层级、标准版本、启停状态；
- `industry_templates` / `industry_template_versions`：行业包与版本；
- `field_definitions`：字段编码、标签、类型、单位、必填、默认值、枚举、校验、敏感级；
- `entity_field_bindings`：字段适用于客户/供应商/产品/订单/项目/员工/设备等哪些实体及页面；
- `company_industry_settings`：法人公司选择的主行业/辅行业、启用版本；
- `custom_field_values`：扩展值；内置模板只读，客户调整做覆盖层，避免升级覆盖客户配置。

部署时流程应为：**选择行业 → 预览新增字段 → 选择主/辅模板 → 校验冲突 → 保存配置 → 初始化示例字段（不灌真实业务数据） → 生成部署报告**。切换行业必须显示字段差异和历史值处理方式，不能直接删字段。

#### 3.2.2 行业目录与交付策略

建议以用户确认的国内标准目录为骨架；候选为 GB/T 4754—2017 的门类/大类，标准版本需用户最终确认。门类候选包括：农林牧渔、采矿、制造、电热燃气及水生产供应、建筑、批发零售、交通运输仓储邮政、住宿餐饮、信息传输软件和信息技术服务、金融、房地产、租赁和商务服务、科学研究和技术服务、水利环境和公共设施管理、居民服务修理和其他服务、教育、卫生和社会工作、文化体育娱乐、公共管理社会保障和社会组织、国际组织。

为避免一次性做 20 套“只有名字不同”的空模板：

1. 所有门类先提供**通用字段兜底**；
2. 第一批做 6 个深模板：机械设备制造、通用制造、批发贸易、专业服务、物流运输、软件/信息技术服务；
3. 再按客户行业补齐其他深模板，模板有版本和验收样例。

字段差异示例：

| 行业 | 重点字段示例 |

## 六、风险与提醒

1. **SQLite 放网络共享是高风险设计债**：WAL、锁语义和断网会造成写入失败甚至损坏；两机主库必须走真正数据库服务。
2. **不要让 Web 控制台拥有 OS 管理员权限**：RDP/防火墙/服务管理应由本机提权助手执行，并记录操作人与回滚命令，否则一个 Web 漏洞等于服务器失守。
3. **明文凭据必须马上收口**：默认 SQL 密码、`dbconfig.json`、`deploy.conf`、部署报告中的管理员口令都会进入备份和工单；应使用凭据保险箱/环境注入并全程脱敏。
4. **M108 不完成，六类部署只能交付一半**：云数据库、云算本地数、本地应用+数据库服务器都不能靠“生成配置文件”冒充可用。
5. **行业字段不能继续硬编码**：否则每增加一个行业都会改表、改页面、改导出，后期迁移成本呈倍数增长。
6. **三方接口不能各写一套**：鉴权、Webhook、幂等、重试、限流、日志、吊销必须先统一；否则接口越多，泄密和重复写入风险越高。
7. **数据范围需做真实接口回归**：基础权限模型已完成，但旧业务数据缺少组织轴或查询未过滤时，仍可能跨公司泄露；AI 查询口尤其要审计。
8. **审批回调需可补偿**：财务报销不能接受“审批成功但报销单未更新”；回调失败必须可见、可重试且幂等。
9. **备份不等于容灾**：必须定期做恢复演练、记录恢复耗时和校验结果；对象存储备份还需加密、版本保留与删除保护。
10. **真实数据会被自动复制到更多产物**：若 M113 不先做，行业模板、部署报告、软著文档、`dist/`、测试截图都会继续扩散旧公司信息。
11. **发布包必须有自动门禁**：仅靠人工删除 `.db/.log/uploads` 不可靠，应在构建脚本中扫描敏感词和禁止文件，命中即失败。
12. **性能推荐必须基于基准测试**：硬件表只能是起点；需记录版本、数据量、并发模型、P95 和备份/恢复时间，避免销售承诺超出单进程架构边界。
