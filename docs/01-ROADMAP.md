# Felix 企业管理平台 — 演进路线图

> **每晚迭代的调度依据。** 状态图例：
> `⬜` 待开发　`🟨` 进行中　`✅` 已完成　`⏸` 阻塞/暂缓
>
> 每晚任务规则：按表格顺序取**第一个 `⬜` 且其依赖全部 `✅`** 的模块开工。
> 完成后把状态改为 `✅`，在 `02-PROGRESS.md` 追加日志，然后停下（不要贪多）。
> 一个模块若当晚做不完，标 `🟨`，次晚继续。

---

## 完成标准（DoD）—— 每个模块必须全部满足才算 ✅

1. **迁移**：`core/schema.py` 追加 `_vNNN`（只追加，不改已发布的），建表 + 索引 + 注释
2. **后端**：`modules/<域>.py` 提供 router，CRUD + 列表筛选 + 状态流转；写权限点校验
3. **权限**：`core/permissions.py` 注册权限点，并分配进对应内置角色
4. **枚举**：模块顶部集中定义，不散落魔法字符串
5. **前端**：`static/js/pages/<name>.js` 一个页面，注册进 `app.js` 路由与菜单
6. **种子**：`seed.py` 或模块内 seed 函数灌入演示数据（幂等）
7. **冒烟**：`tools/smoke_test.py` 启动服务 → 调关键 API → 断言 200/JSON → 关停
8. **文档**：本表状态更新 + `02-PROGRESS.md` 写清「做了什么/遇到什么坑/下一步」

## 依赖铁律

- Phase 0 的 M001–M005 **必须先完成**，其余所有 Phase 都建在其上
- 任何"申请→审批"类单据（M011/M021/M022/M024/M050/M070/M071/M083）**依赖 M005**
- 成本核算 M073 依赖 BOM M060 + 报工 M062 + 库存 M053
- 驾驶舱 M090 依赖至少 Phase 1–4 的数据

## 发布节奏

- 每完成 **一个 Phase 或累计 3 个模块** → 打包 `felix-quote-<版本>.rar` → 替换资料库节点
- 大版本里程碑：2.0.0（组织主干完成）→ 2.1.0（HR+行政+OA）→ 2.2.0（供应链+生产）
  → 2.3.0（财务+研发）→ 2.4.0（BI+平台）
